# Copilot Instructions for Mercury Autonomy Project

## Project Context

The **mercury_autonomy** project is a BehaviorTree-based autonomy system for the Mercury stack (an underwater robot). It's a modern replacement for riptide_autonomy with the following key characteristics:

- **Language**: C++17, ROS2 (Iron/Jazzy)
- **Location**: `/home/bobdobchob/osu-uwrt/development/software/src/mercury_autonomy/`
- **Core Library**: BehaviorTree.CPP 4.9.0 (vendored in `dependencies/BehaviorTreeCPP/`)
- **Build System**: CMake with colcon for ROS2 integration
- **Coding Style**: Modern C++, ROS2 best practices, header-only where practical

## Key Design Decisions

### 1. BehaviorTree.CPP as Git Subtree
- Allows custom modifications while maintaining upstream sync
- The library is built in-place and linked by mercury_autonomy
- Use `git subtree pull` to sync with upstream
- All library code changes are tracked in the main repository

### 2. Three-Layer Architecture
- **AutonomyCore**: Manages tree factory and loading logic
- **TreeManager**: Handles asynchronous tree execution in background thread
- **AutonomyActionServer**: ROS2 interface for goals and feedback

### 3. Custom Node Framework
- Templated base classes for easy custom node creation
- Example templates provided for action and condition nodes
- Nodes access ROS2 node through `get_node()` for communication

### 4. Header-Heavy Design
- Many implementations are header-only for ease of custom node creation
- Low compile-time overhead for consumer code
- Follows BehaviorTree.CPP library conventions

## Important Technical Details

### Tree Execution Model
- Trees are executed via `TreeManager` in a separate thread
- Tick rate is configurable (default 10 Hz)
- Thread-safe pause/resume functionality
- Status updates available via `get_tree_status()`

### API Details
- **TreeManager**: Takes ownership of `BT::Tree` via rvalue reference
- **Tree Loading**: `AutonomyCore::load_tree()` returns `BT::Tree` (not pointer)
- **Node Registration**: Templated `register_custom_node<NodeType>()`
- **Tree Ticking**: Uses `tree->tickOnce()` method (not `tickRoot()`)

### Build Process
```bash
colcon build --packages-select behaviortree_cpp mercury_autonomy
```

The system automatically:
- Builds BehaviorTree.CPP from source in dependencies/
- Links mercury_autonomy against local library
- Installs headers and resources appropriately

## Common Tasks

### Adding a Custom Node
1. Copy `include/mercury_autonomy/nodes/example_action_node.h`
2. Rename and modify the class name
3. Implement `onStart()`, `onRunning()`, `onHalted()` methods
4. Register in action_server.cpp:
   ```cpp
   auto builder = [this](const std::string& name, const BT::NodeConfig& config) {
     return std::make_unique<MyNode>(name, config, shared_from_this());
   };
   autonomy_core_->register_custom_node<MyNode>("MyNode", builder);
   ```

### Modifying BehaviorTree.CPP
1. Edit files in `dependencies/BehaviorTreeCPP/`
2. Changes are git-tracked automatically
3. Rebuild with `colcon build`
4. To contribute upstream: use `git subtree push`

### Creating a New Behavior Tree
1. Create XML file in `trees/` directory
2. Use registered node IDs in `<Action>` and `<Condition>` elements
3. Load via `autonomy_core_->load_tree("path/to/tree.xml")`
4. Pass to TreeManager for execution

### Testing Changes
- **Build test**: `colcon build --packages-select mercury_autonomy`
- **Debug logs**: Set `--log-level mercury_autonomy:=DEBUG`
- **Tree tests**: Create executable that loads/ticks trees manually

## Code Style Guidelines

### C++ Conventions
- **Standard**: C++17
- **Naming**: snake_case for functions/variables, PascalCase for classes
- **Headers**: Guard all headers with `#ifndef MERCURY_AUTONOMY__FOO_H_`
- **Namespaces**: Everything in `mercury_autonomy` or `mercury_autonomy::nodes`

### ROS2 Conventions
- Use `RCLCPP_*` logging macros (INFO, WARN, ERROR, DEBUG)
- Access node via `get_node()` in custom nodes
- Use `declare_parameter()` for configuration
- Return status via `BT::NodeStatus` enum

### Documentation
- Document public APIs with Doxygen-style comments
- Example: See `include/mercury_autonomy/autonomy_core.h`
- Include usage examples in class documentation

## Debugging Tips

### Build Issues
- Check that `CMakeLists.txt` has all required `find_package()` calls
- Verify package.xml has all `<depend>` entries
- Ensure includes match the actual file paths
- BehaviorTree.CPP is built using `ament_cmake` if ROS2 detected

### Runtime Issues
- Enable debug logging: `--log-level mercury_autonomy:=DEBUG`
- Check tree XML for invalid node IDs
- Verify custom nodes are registered before loading tree
- Monitor thread status with `tree_manager->is_running()`

### Tree Execution Issues
- Trees return `NodeStatus::RUNNING` while executing
- Use `tree_manager->stop_execution()` to halt background thread
- Check `onHalted()` is implemented for cleanup
- Verify tick rate is reasonable for your nodes

## Important Warnings

⚠️ **Do not delete** the `dependencies/` directory - it contains the vendored BT library
⚠️ **Tree XML paths** must be relative to installation directory or use absolute paths
⚠️ **Custom nodes** must implement all pure virtual methods from base classes
⚠️ **Thread safety** - TreeManager runs in separate thread; use thread-safe ROS2 APIs
⚠️ **Cleanup** - Implement `onHalted()` to stop any ongoing operations

2. **Test compilation**: Ensure no new errors introduced
3. **Update documentation**: Keep Project.md and comments current

7. **Document API changes**: Update both headers and markdown docs
